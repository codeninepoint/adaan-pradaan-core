Order Fulfillment & Delivery Lifecycle

Complete end-to-end design for what happens after a buyer places an order — from vendor notification through inventory reservation, packing, shipment, real-time tracking, and final delivery confirmation — and how every party stays in sync via outbox events.

Phase 3 — Not yet implemented
Builds on J48 (Buyer Checkout) which exists
New journeys J53 – J62
New tables inventory, inventory_reservations, shipments, tracking_events
Fulfillment type SHIP_PHYSICAL (primary scope)
⚠️

What exists today (J48): A buyer can checkout and POST /marketplace/orders to create an order with status = "placed" and tracking: null. Nothing moves after that. There is no vendor notification, no inventory check, no shipment, no tracking update. The journeys below are the design for Phase 3.
